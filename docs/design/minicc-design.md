# minicc 编译器设计文档

- 状态：设计基线（V1 已实现，本文档面向 V2\~V4 演进）

- 范围：mini-os 板载自研 C 编译器 `minicc`（MIT，替代 GPL 的 cc500）

- 相关代码：[tools/minicc/](../../v2-c-kernel/tools/minicc/) · [test\_minicc.sh](../../v2-c-kernel/tests/test_minicc.sh) · [cc500 深度审计](../history/external-reviews/mini-os-cc500-deep-audit.md)

***

## 1. 背景与动机

| 决策              | 理由                                                                                   |
| --------------- | ------------------------------------------------------------------------------------ |
| 自研而非在 cc500 上迭代 | cc500 为 GPL-2.0；仓库整体为 MIT。持续扩展 GPL 组件使每次迭代都携带许可传染风险，自研可彻底断线                          |
| 不追求 GCC 级别能力    | 定位是**教学内核的板载编译器**：让用户在 mini-os guest 内完成"写-编-跑"闭环，并最终实现编译器**自举**（用 minicc 编译 minicc） |
| 许可              | 全新实现（非 cc500 派生），SPDX: MIT                                                           |

编译产物运行环境特殊：**不使用宿主 libc/加载器，直出 ELF32 并由 mini-os 内核** **`elf_load`** **按 PT\_LOAD 映射**；程序退出码经 `sys_exit(ebx)` 传回 shell。这决定了验证体系（第 9 节）与外部项目不同。

***

## 2. 设计目标与非目标

目标：

1. 编译器本体代码**简洁可读**（V1 约 700 行），每个特性可被一个测试用例证明。
2. 语言子集**契约式锁定**：明确"支持什么 / 拒绝什么"，拒绝即编译期静态报错，绝不产出错误机器码。
3. 可验证性优先：宿主层（秒级、无内核）+ guest 层（真机语义）+ 自举不动点（P1==P2）三层验证。
4. 最终自举：编译器本体最终用自身子集编写，通过"字节一致不动点"证明。

非目标（刻意排除）：

- 完整 C 标准、优化、预处理、`long double`、VLA、可变参数、结构体成员重排等。

- 与 GCC 的**编译过程**逐行一致（含错误信息文本、指令调度）。

***

## 3. 外部架构原则评审

外部专家《C-mini 编译器架构设计参考原则 v1.0》方向正确，是通用编译器工程最佳实践汇编；但其中有若干条面向"LLVM 级 / 团队协作 / 宿主工具链"场景，需按本项目实际（教学自举、单文件、guest ABI）裁剪。逐条结论如下：

| # | 原则                       | 结论                    | 理由与本项目落点                                                                                                                                                                                    |
| - | ------------------------ | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | 管道-过滤器 + IR 宪法           | **采纳，降级为"数据结构契约"**    | 教育级单遍编译器（tcc 早期、chibicc、cc500）不建完整 IR；把"ASTNode / Sym / Patch 的内存布局是项目宪法"落实到**数据结构契约**（第 4.2 节），阶段边界明确即可，不引入中间 IR 层                                                                         |
| 2 | 数据不可变 + Arena            | **完全采纳**              | guest 无 libc、靠 brk；Arena 线性分配 + 编译结束一次性释放与运行环境天然契合，且规避 AI 生成代码的悬垂指针/泄漏（第 5 节）                                                                                                               |
| 3 | 契约式子集锁定                  | **完全采纳**              | 已实践（拒绝 `0x10`、全局非常量初始化等）；维护"特性↔测试"清单（第 6 节），缺特性必须编译期报错而非生成坏码                                                                                                                                |
| 4 | 差分验证等价黑盒                 | **方向采纳，载体替换**         | 产物只能在 mini-os guest 运行（`int $0x80` 是 mini-os 系统调用号，宿主 qemu-i386 无法执行），无法"宿主跑 ref/test 两程序比对"。替换为三层等价验证：guest 退出码断言 + **自举不动点（P1==P2，比差分更强）** + 宿主语义对照（第 9.4 节）。`-O0 -fno-builtin` 建议采纳于语义对照 |
| 5 | 错误恢复优先于完美诊断              | **部分采纳**              | 自举编译器无需 rustc 级恢复；保留 fail-fast + token 上下文（V1 已实现），错误分类规范化（第 8 节），"跳过到 `;`/`}`"式恢复列为可选增强                                                                                                    |
| 6 | 模块级双轨测试 + Mock           | **完全采纳**              | 宿主层已可秒级测编译器核心；V2 引入 AST 后，语义分析器可直接喂手工构造的 AST（绕开词法/语法），利用 `tests/utest.h`；覆盖率目标为核心逻辑函数级 assert，不追求行覆盖（第 10 节）                                                                                |
| 7 | CompilerContext 句柄 + 禁全局 | **采纳为 V2 演进项，不阻塞 V1** | V1 采用全局状态（chibicc/cc500 同款），以最快打通已验证；V2 引入指针后 struct 可表达 context，逐步收敛为"状态经 ctx 指针传递"，纪律：**不再新增全局可变状态**（第 10.1 节）                                                                            |

路线图建议（**垂直切片**，而非水平分层）：**完全采纳**。V1 的实际迭代过程即垂直切片：`int main(){return 0;}` 端到端 → 变量/四则 → 函数/递归 → 全局 → 逻辑运算，每加特性都走"语法→生成→验证"闭环（第 11 节）。

## 4. 总体架构

### 4.1 阶段划分（Pipeline）

```
源文件 ─▶ [词法 Lexer] ─▶ token 流 ─▶ [语法+语义 Parser] ─▶ 符号表/补丁表 ─▶ [代码生成 Codegen] ─▶ ELF 字节流
                                                                  ▲
                                            ASTNode（V2 起作为 Parser 与 Codegen 的显式契约）
```

- 词法（`next_tok`）：单字符超前，产出 token 串 + 类别（word/number/operator）；负责注释剥离与坏字面量拒绝（如 `123abc`）。

- 语法/语义（递归下降）：表达式按优先级分层（`mul→add→rel→eq→land→lor→expr`）；标识符解析时产出左值地址（`T_LVAL`），二元运算消费时加载（`T_RVAL`）。

- 代码生成：直接向 `code` 缓冲发射 x86-32 字节（ebp 栈帧 + 栈式求值），符号引用/控制流跳转先发占位、收尾统一回填（补丁表）。

- **阶段接口纪律**：词法只经 token 流与 Parser 通信；Parser/Codegen 只经符号表、补丁表、（V2 起）AST 通信；禁止跨层访问源码缓冲/机器码细节。

### 4.2 数据结构契约（"宪法"层）

以下结构体的内存布局为项目契约，优先级高于实现细节；V2 演进时只允许增加字段，不允许改变语义：

```c
/* token（词法输出；V1 为全局缓冲，V2 迁入 ctx） */
struct Token { char text[64]; int kind; };   /* kind: WORD / NUM / OP */

/* 符号（V1 即结构体数组，V2 迁入 ctx 并支持作用域链） */
struct Sym { char name[32]; int kind; int val; };
/* kind: K_FUNC / K_GLOBAL / K_LOCAL / K_ARG
 * val : FUNC→代码偏移(未定义=-1)  GLOBAL→数据偏移  LOCAL/ARG→槽位序号 */

/* 补丁（延迟回填：call 目标 / 全局地址 / 控制流跳转） */
struct Patch { char name[32]; int pos; int kind; };  /* kind: P_CALL / P_ADDR */
struct Lab   { int pos; int kind; int target; };     /* kind: L_COND / L_JMP */

/* AST 节点（V2 引入；当前单遍直接生成，无 AST） */
struct Node { int kind; struct Node *l, *r; int val; /* 语义类别 T_LVAL/T_RVAL */ };
```

补丁机制要点（V1 已验证）：符号引用在生成时记录 `(name, pos)`，定义处记录偏移，收尾统一回填；**同一目标被多条跳转引用时，每条跳转必须有独立补丁记录**（V1 曾因共享标签只回填最后一处而产出错误跳转，该缺陷已在测试中锁定）。

### 4.3 单遍 vs AST 决策

| 阶段  | 方案              | 理由                                                                 |
| --- | --------------- | ------------------------------------------------------------------ |
| V1  | 单遍直接生成（无 AST）   | 最小子集（int-only、无指针/数组）下，左值/右值 + 补丁表足以正确生成；cc500/chibicc 同款，代码量最小    |
| V2+ | 引入显式 AST 作为前端产物 | 指针/数组下标/字符串需要"先解析后决定语义"（如 `a[i]` 的读写选择），且语义分析器可脱离词法被 Mock 测试（原则 6） |

决策规则：**当"解析时无法立即确定生成策略"的特性出现（如解引用、复合类型），立即引入 AST，不继续堆叠单遍特例**。

## 5. 内存管理：Arena

- 全局唯一 **Arena**：按 brk 线性分配，编译结束时一次性释放（guest 下即放弃 brk 增长区间）。

- 所有 AST 节点、符号表、token 缓冲、code 缓冲均在 Arena 分配；**编译期间不做任何 free**。

- 与运行环境的契合：guest 无 libc（`-nostdlib`）、堆经 `SYS_BRK`；宿主由 host\_crt 用静态竞技场模拟同一 syscall3 接口，同一份源码双端构建。

- 纪律：编译器内**禁止**引入"按对象释放"的 malloc/free 模型；`xmalloc` 失败即报 `out of memory` 并退出（属 fatal，见第 8 节）。

V1 现状：`code` 缓冲（2 倍增长）、`syms`/`patches`/`labs` 定长数组已是"类 Arena"雏形；V2 正式化为一个 `Arena { base; cur; end; }` 并统一入口。

## 6. 语言子集规范（Feature Matrix）

原则：**每增一个特性必须附带一个测试用例**（宿主或 guest 层），并同步更新本表；**拒绝"顺带支持"**。

### 6.1 V1（已实现并通过 `make test-minicc`）

| 类别  | 支持                                                                                  | 测试锚点                                    |
| --- | ----------------------------------------------------------------------------------- | --------------------------------------- |
| 类型  | `int`（32 位有符号）                                                                      | 全用例                                     |
| 字面量 | 十进制整数                                                                               | 拒绝 `0x10`/`123abc`（宿主 t\_hex/t\_mixnum） |
| 变量  | 局部/参数/全局（全局仅常量初始化）                                                                  | 全局 + while 累加 guest 用例                  |
| 运算符 | `+ - * / % < <= > >= == !=`、逻辑与或（`&&`、`\|\|`）、`!`、一元负号、`=`                          | 17/5 除模、fact(5) 递归、`&&`/`!` guest 用例    |
| 语句  | `{}`、声明、`if/else`、`while`、`return`、表达式语句                                            | guest 运行语义                              |
| 函数  | 多参数、递归、前向调用                                                                         | `fact(5)==120`                          |
| 注释  | 块注释、`//` 行注释                                                                        | 未闭合注释报错（宿主 t\_comment）                  |
| 拒绝  | 结构体/预处理/`for`/`do`/`switch`/`break`/`continue`、全局非常量初始化（字面量/字符除外）、数组初始化/数组参数/数组名无下标 | 编译期报错断言                                 |

### 6.2 V2 进度（AST + 指针 + 字符串/char + syscall3 + 数组已完成，待 L4 语义对照）

- ✅ AST 引入（V2a）：Parser 建树 + Codegen 遍历，替换 V1 单遍直接生成；int-only 语义经测试锁定等价。

- ✅ 类型系统 + 指针（V2b）：`TY_INT/TY_PTR`；`int*` 声明/参数/全局；`&` 取地址、`*` 解引用（可读写）；指针算术 `p+n` 按元素尺寸（4 字节）缩放；赋值/初始化/解引用/取地址均编译期类型检查。

- ✅ 字符串/char（V2c）：`TY_CHAR`（无符号）加入；`char` 变量/全局/参数、`char*` 指针（算术按元素尺寸 1 缩放、读写按 8 位 `movzbl/mov %al`）；字符字面量 `'A'`（支持转义）；字符串字面量入只读数据段、表达式为隐式 `char*`，转义 `\n \t \\ \" \' \0 \xNN`（≤254 字节，EOF/换行守卫；借鉴 cc500 已验证的解码，规避其 F-3 自噬）。

- ✅ 数组（V2d）：`int a[N]` / `char s[N]` 全局/局部定长；`a[i]` 读写（元素按类型取宽），`&a[i]` 可作指针；帧布局由 4 字节槽改为**字节偏移**（数组紧凑 len×元素尺寸，标量 4 字节对齐，帧 ≤4KB 编译期拒绝）；下标边界不检查、数组名无下标/数组初始化/数组参数编译期拒绝（UB 由用户负责）。

- ✅ 系统调用面（V2c）：产物隐式调用 `syscall3(n,a,b,c)` 时编译器自动生成 `int $0x80` 机器码 stub（参数按 minicc 约定映射 eax=号 ebx=a ecx=b edx=c；用户显式定义则作普通函数），从而支持 `sys_print`/读写文件——guest "写-编-跑"从"纯计算"走向**可观察 I/O**（测试断言产物运行期输出）。

### 6.3 明确拒绝清单（编译期静态报错，不产出坏码）

`long double`、`double`/`float`、`unsigned`、`struct/union/enum`、VLA、可变参数、位域、`goto`、预处理指令、位运算（`& | ^ << >>`，V2 视需要再议）、隐式指针转换、取未定义函数地址、**多级指针** **`int**`（V2b 起）**、解引用非指针、对非左值取地址、指针/整型混赋。

## 7. 代码生成与 mini-os ABI

### 7.1 ELF 直出布局（不经过汇编/链接器）

```
0x00  ELF32 头 + 1×PT_LOAD（link=0x800A0000，flags=RWX，p_filesz/memsz 收尾回填）
0x54  入口 stub: call main ; mov %eax,%ebx ; xor %eax,%eax ; int $0x80
0x5F  <全局数据> <函数体…>
```

- 退出码契约：`sys_exit` 读 `ebx`（见 `usermode.c` 的 `sys_exit(code=a=ebx)`），故 stub 把 `main()` 返回值搬到 `ebx`、`eax=0`。

- 内核加载契约：`elf_load` 按 PT\_LOAD 原样放置（`load_base=0` 路径）；入口 `e_entry=0x800A0054`。

### 7.2 调用约定与栈帧（自洽，仅编译器自身消费）

- 标准 cdecl 栈帧：`push ebp; mov ebp,esp; sub esp,frame`；局部 `[ebp-4i]`。

- 参数**从左到右求值并逐个 push**；被调函数第 i 个形参位于 `[ebp+8+4*(n-1-i)]`。

- 返回值在 `eax`；`eax/ebx/ecx/edx` 调用者保存，其余被调用者保存。

- 帧大小在函数体解析完成后回填（prologue 的 `sub esp,imm32` 占位补丁）。

> 说明：该约定与宿主 cdecl 不同（宿主要求从右到左压参），但因编译器同时生成调用方与被调方，任何自洽约定皆可；**与 CRT/内核的接口只有入口 stub 一处**，已锁定。

### 7.3 自举约束与实现（V3 达成）

- 编译器本体以自身子集编写：`tools/minicc/minicc_self.c`（`/minicc-self`，P1）。子集纪律见该文件头部注释（无 struct/enum/typedef/static/include/宏；无 for/switch/`+=`/`++`/`--`/`?:`/多级指针；无函数原型；全部函数返回 int）。

- AST 以**并行数组 + int 句柄**表达（无 struct）：节点字段拆成 `nkind/nty/nbty/nlen/nl/nr/na/nb/nnext/nval/nvkind/nvslot/nival/nnargs/nnlocals` 等全局数组，句柄即下标（0 保留为 NULL）。这是子集纪律下承接 V2 结构体 AST 的等价物。

- 自举验证链（L3，已验证）：
  1. 宿主 gcc 编 `minicc.c + host_crt.c` → hostminicc；
  2. hostminicc 编 `minicc_self.c` → **P1**（嵌入 initramfs 作 `/minicc-self`；其源码同时嵌入作 `/minicc.c`）；
  3. guest 内 P1 固定编译 `/minicc.c` → `/out.elf`（**P2**）；
  4. shell `miccboot` 命令比对 P1 与 P2 **逐字节一致** —— 自举不动点达成（`tests/test_miccboot.sh` / `tests/dbg_miccboot.sh`）。

- 自举过程的已知问题与对策：
  - 节点池越界写穿全局 `nn`（BUG-038）：并行数组 `[8192]` 的有效下标 0..8191，`node_new` 守卫用 `nn >= NMAX - 1`，否则 `nnlocals[8192]` 会写穿到相邻全局把节点计数清零。
  - 十六进制全局初值（BUG-039）：`CODE_BASE = 0x800a0000` 需按 `0x` 前缀解析，旧十进制环会把 `x/a` 当数字位算成垃圾值，P1 运行时寻址全偏。
  - 符号查找从后往前（最近声明优先）：局部变量遮蔽同名全局函数。
  - UTF-8 非 ASCII 注释字节：`peek/peek2` 用 `& 255` 无符号读取，避免有符号 char 负值被误判为 EOF。
  - 类型检查放宽：`type_eq` 允许右值 int 赋给指针，支撑 `xmalloc`（`brk` 系统调用）返回 int 地址赋给 `char*`。
  - 资源上限：节点池 8192、`PATCH_MAX=4096`、`code_cap=860000`（产物含全局数组零填充数据段 + 文本约 686KB）。
  - 宿主侧逻辑快速验证：gcc 直编 `minicc_self.c + host_crt.c`（`-Dmain` 改名避冲突 + `-include` 声明 syscall3）得宿主版 S，S 编 `minicc_self.c` 得 Q，`Q == P1` 逐字节一致 —— 证明 minicc_self.c 逻辑与 minicc.c 语义完全一致，机器码/运行期差异只可能来自 codegen（已被 guest 内 P1==P2 排除）。

## 8. 错误处理策略

| 类别                     | 行为                                       | 说明                             |
| ---------------------- | ---------------------------------------- | ------------------------------ |
| Fatal（内存耗尽、输入超限、未定义符号） | 打印诊断 + 退出码 1                             | 不尝试恢复                          |
| Syntax（语法/语义错误）        | 打印 `minicc: error: <消息> [token]` + 退出码 1 | V1 已实现 token 上下文；不追求与 GCC 行号一致 |
| 恢复（可选增强，V2 评估）         | 遇到 `;`/`}` 前跳过 token 继续                  | 用于一次编译报出多个错误；不改变已生成代码的正确性      |

- 诊断格式规范（V2 起）：`minicc: error: <行>:<列>: <消息> [token]`；行/列由 Lexer 维护。

- 纪律：**任何"不支持特性"必须走诊断路径**，禁止静默生成错误机器码（原则 3）。

## 9. 验证体系（三层 + 差分对照）

本项目验证体系的特殊性：产物只能在 mini-os guest 内运行，故外部专家建议的"宿主双程序对比"需替换为如下分层：

| 层                | 内容                                                                         | 速度/依赖                | 用例                      |
| ---------------- | -------------------------------------------------------------------------- | -------------------- | ----------------------- |
| L1 宿主单测          | hostminicc（minicc.c + host\_crt.c 直编 Linux 程序）：错误路径退出码、产物 objdump/od 编码断言  | 秒级，仅 gcc/qemu-i386   | `test_minicc.sh` \[2] 段 |
| L2 guest 端到端     | qemu 内经 `micc <src> <out>` 编译并运行，断言退出码语义                                   | 分钟级，qemu-system-i386 | `test_minicc.sh` \[3] 段 |
| L3 自举不动点         | P1==P2 逐字节一致（V3 已启用：`minicc-self` 编 `/minicc.c` → `/out.elf`，`miccboot` 比对）                          | 分钟级                  | `test_miccboot.sh` / `dbg_miccboot.sh` |
| L4 语义对照（新增，V2 起） | 同一测试源：宿主 gcc `-O0 -fno-builtin` + 迷你 CRT 编译运行取期望值；guest 内 minicc 产物退出码与之比对 | 融入 L2                | 见 9.4                   |

### 9.4 语义对照细则（原则 4 的本项目落地）

- 测试源约束：int-only 纯计算、无系统调用（保证宿主 gcc 可直接运行）；期望值由"运行 ref"得到，而非手工抄写，避免人肉算错。

- 宿主 gcc 固定 `-O0 -fno-builtin`：关闭优化与内置替换，使 GCC 行为接近朴素翻译，减少 UB 噪声。

- 比对维度仅 `exit code`（stdout/stderr 在 V2 引入字符串后加入），**不比对汇编/IR**。

## 10. 模块化与可测试性

### 10.1 CompilerContext 演进（原则 7 落地）

- V1：全局状态（`code/syms/patches/labs/src/tok/cur_*`），已在 `-Werror` 下保持可维护。

- V2 起：状态收敛进 `struct CompilerContext`，以指针作为编译入口参数；编译器本体子集可表达 struct 后逐步移除全局可变状态。

- **纪律：不得新增全局可变状态**；只读常量（编码表、ELH 头）除外。

### 10.2 Mock 单测（原则 6 落地）

- V2 引入 AST 后，语义/生成函数接受 `Node*` 输入，宿主层可直接在测试中手工构造 AST 调用（绕开 Lexer/Parser），实现模块级隔离。

- 覆盖率目标：**核心逻辑函数级 assert**（如算术节点求值、类型兼容、地址偏移计算），不设行覆盖率门槛。

- 载体：`tests/utest.h` 宿主单测框架 + `test_minicc.sh` L1 段。

## 11. 路线图（垂直切片）

每步闭环："更新语法 → 更新生成 → 补测试（L1+L2）→ 全绿"。

| 版本   | 切片目标                                    | 关键产出                                                                                         |
| ---- | --------------------------------------- | -------------------------------------------------------------------------------------------- |
| V1 ✅ | `int main(){return 0;}` 起逐特性打通 int-only | 700 行编译器 + `micc` 命令 + `make test-minicc` 全绿                                                 |
| V2 ✅ | 指针/字符串/数组/下标 → 产物可调 `syscall3`（I/O 可观察） | AST（V2a）+ 指针（V2b）+ 字符串/char/syscall3 stub（V2c）+ 数组（V2d）完成，guest 已断言产物运行期输出与数组运行语义；L4 语义对照待上线 |
| V3 ✅ | 编译器自举                                   | `minicc_self.c` 全子集编写（并行数组 + int 句柄）+ P1==P2 不动点验证（`miccboot`）+ L3 启用（`test_miccboot.sh` 全绿） |
| V4+  | struct、`for/switch`、位运算等按需扩展            | 特性↔测试清单滚动更新；cc500 退役评估                                                                       |

风险提示：V2 的 AST 引入是对 V1 单遍生成的**结构性重构**，应在一个切片内完成并保持 L1/L2 全绿后合入，避免长分支。

## 12. 风险与取舍

| 风险                       | 缓解                                                  |
| ------------------------ | --------------------------------------------------- |
| 单遍生成的特例堆叠导致复杂度失控         | 4.3 决策规则：出现"解析时无法立即决定生成"即切 AST                      |
| 自举使源码受子集约束（无 libc、无灵活语法） | 特性先在编译器源码内自用（dogfooding），逐步收紧                       |
| 与 GCC 的语义差异（UB 场景）       | L4 语义对照 + 文档明示 UB 由用户负责（如除零、数组越界）                   |
| guest 内资源受限（栈/堆）         | Arena 线性分配；测试源码限制在 writefile 单行 128B 内（heredoc 可放大） |
| AI 生成代码的全局状态污染           | CompilerContext 纪律（10.1）+ 阶段接口契约（4.1）               |
