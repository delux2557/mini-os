## 任务 1（P0，成本最低）：GVAR hex 初始化器回归用例——锁定 BUG-039

**目标**：给 BUG-039 的修复加测试，防止回归。

**背景**：BUG-039（GVAR 十进制环把 `0x800a0000` 的 `x`/`a` 当数字位，算出 `0xB1F37610` 垃圾值，导致自举 CODE\_BASE 崩坏）已在 `minicc.c` 修复，但 `test_minicc.sh` 目前只有**表达式层** hex（`t_hex`：`0x10/0xff/0x0a`）和 guest 位运算+hex（`0x30`），**没有** **`int G = 0x800a0000;`** **形态的 GVAR 初始化器用例**。这个 bug 是 P1==P2 的关键前提，值得一条测试锁死。

**参考路径**（仅供选择）：

- 宿主一条：`int G=0x800a0000;` + 运行语义断言 `G==2148139008`（比"compiled OK"更强，能抓住值错）；

- guest 一条对应用例（注意沿用现有的 <128B 或 heredoc 约定）；

- 可顺带决定是否覆盖 `0X` 大写前缀、hex 回绕边界（`0xFFFFFFFF`）——你判断值得覆盖哪些。

**验收建议**：新用例在当前代码通过；**临时回退 BUG-039 修复时该用例必须 FAIL**（自证测试有效性，与项目防假绿哲学一致）。

## 任务 2（P1）：文档 §6.2 帧布局措辞与实现对齐（F9）

**目标**：消除文档与实现的表述分歧。

**背景**：§6.2 写「标量 4 字节对齐」，但实现是**纯字节偏移**分配（实测：`char s[3]` 后 `int x` 落 `-7(%ebp)`，未对齐 4 边界）。x86 非对齐访问容错，guest 实测无碍，所以这是**措辞失准**而非功能 bug。

**两个方向及其权衡**：

- **(a) 改文档如实描述**（字节偏移、未对齐，x86 允许）：零风险，推荐起点；

- **(b) 改实现对齐到 4 边界**：更"整洁"且利于未来移植，但改变已验证的帧布局行为，需全量回归，且对当前单目标（i386）收益有限。

**验收**：文档描述与代码行为完全一致，第三方读文档能准确预测帧布局。

## 任务 4（P2，规划项）：Mock AST 单测 与 差分对拍（F2，原则 6）

**目标**：让设计文档原则 6「模块级双轨测试」名实相符，并把「对参考编译器差分」走通。

**背景**：`tests/utest.h` 已存在，`minicc.c` 未使用，当前测试纯黑盒。黑盒已很强（44+guest+miccboot），单测的增量价值主要在：错误路径精细断言、重构时快速定位（配合任务 5）。

**需要你权衡的点**：

- `minicc.c` 单文件、全量全局、`minicc_main` 特化入口——引入单测需定链接方式（测试 driver `#include minicc.c` 或提取可测层）；

- **与任务 5 联动**：先做 CompilerContext 收敛，单测注入点会完全不同，顺序值得先想清；

- 另一合法解法是**修订原则 6 表述**（承认当前以黑盒为主、Mock 列为演进项）——"文档对齐实现"同样是还债。选哪条路由你定。

**本次新增方向（差分对拍，见 V4 任务 7）**：受限子集随机生成器 + 宿主 gcc `-O0 -fno-builtin` 参考差分，与设计文档 §9.4 语义对照同源。与 Mock 单测共用一套下单集，可一并规划。

**差分对拍生成器设计约束**（2026-09-05 定，开工前必读）：

1. **生成器形态：特性表驱动 + 动态子集**。每个语法特性注册为一张"特性行"（生成函数 + 适用编译器集 + 依赖 + 权重），目标编译器能力集是**数据（开关）而非代码**；给定某能力集从全表筛出特性后按依赖展开。于是 minicc 全集 / cc500 子集 / 二者公共交集三套玩法天然成立。**以后加特性 = 表加一行 + 一个生成函数**，生成核心 / runner / 比对一字不改。别上完整文法 DSL（把 bug 藏进更黑的一层，投入产出比差），特性表驱动的作坊模式即止。

2. **无 UB = 一票否决的灵魂设计**。被生成程序在 ISO C 下必须语义良定、结果可预测；否则编译器对 UB"做什么都算对"，diff 全部无法归因（这是 Csmith 区别于普通乱拼代码生成器的分水岭）。受限子集不背完整 Csmith 状态表，用三纪律等效达成：

   - **声明即初始化**：变量声明时喂已知常量 → 免"读前必写"状态机；

   - **值域限幅 + 分母非零**：变量约束在窄区间（如 `[-20000,20000]`），算式只做 `±`小量 / `*`小因子，除法分母强制来自字面量或已知非零窄集 → 防有符号溢出与除零；

   - **指针只 bind 同作用域已分配数组** → 免悬垂指针映射；

   - **工程兜底（gcc 哨兵）**：每个用例先宿主 `gcc -O0` 过一遍当"有效性哨兵"，意外边缘行为被良定义路径暴露为 diff 而非无声沉没。

3. **有效性门槛**：用例须能被宿主 gcc `-O0` 接受才算有效——过滤"生成器 bug"而非"编译器 bug"的脏用例，与无 UB 纪律正交。

4. **C-Reduce 缓做**：受限生成器产出的样例本身小、且无 UB 纪律让定位容易；先上一个很薄的 ddmin（delta debugging）缩减器，失败样例真攒成"不小看不了"再上全套 creduce。

**实现进度**（2026-09-05）：两层差分均已落地——
- 宿主 acceptance 差分：`tests/test_diffsynth.sh`（gcc 哨兵 + minicc 接受 + determinism/不挂）；
- **guest 运行语义差分**：`tests/test_diffsynth_guest.sh`（方案 B，`GUEST_DIFF=1` 把随机样本 ds00..ds11 批量嵌入 initramfs，QEMU `run dsXX` 取**运行退码**与 gcc 参考比对；默认构建零侵入，独立 build 子目录）。
- **对比口径**：mini-os `exit_code` 是完整 uint32（负 `return` 显示巨大数如 4294967295），与宿主 gcc/qemu 的 `&0xff` 编码不同 —— 差分统一按 **return 值低 8 位语义**对齐（`&0xff`），故 `return -1` 时 guest=255、宿主 ref=255 判定一致。
- **特性推进**：生成器 minicc 能力集已纳入**位运算** `& | ^ >> ~`（`F_BIT`；刻意避开 `<<`，因有符号左移溢出是 UB）。host/guest 两层差分全绿（位运算样本与 gcc 语义一致）。**动态子集生效**：加特性 = 能力集表加一个 flag + 一段生成函数，核心/runner/比对零改动。
- **覆盖度扩展**：minicc 能力集再纳入**全局变量**（`F_GLOBAL`）/ **数组**（`F_ARRAY`，全元素初始化防读未初始化）/ **指针**（`F_PTR`，bind 数组基址后 `*(p+k)` 解引用，k∈0..ASZ-1 不越界）——保持无UB三纪律。host/guest 两层差分全绿，真实运行语义与 gcc 一致。
- **函数/递归**（`F_FUNC`)：predicate 前插入纯函数`h0=sum(n)`（线性递归，至多 7 层栈帧）与`h1=fib(n)`（双支递归），调用参数=任意窄值表达式再按位掩码 `(e & m)`（m∈{3,7}）限幅到非负窄区间 → 深度/值域有界（sum≤28/fib≤21）、确定终止、无副作用（对负 e 仍得非负）。host 差分 + **guest 运行语义**双双验证 minicc 递归码生与 gcc 逐退码一致（12/12）——真翻到栈帧/调用约定层面。cc500 不给 `F_FUNC`。
- **小结（差分对拍暂告段落）**：特性表驱动 + 动态子集机制已定型——**以后加特性 = 能力集表加一行 + 一个生成函数**，核心/runner/比对零改动；host acceptance + guest 运行语义两层差分已纳入 CI 常跑回归网。差分对拍自此转入"常驻资产"：不设专人追新，遇新特性/重构尾声再往里加特性行即可。
- **cc500 能力集实测校准**：hostcc 探测——cc500 支持 `& | <<` 与 `char`，拒绝 global/array/ptr/`for`/`^`/`~`；据此 `CAPS_CC500` 复认保守正确（不给 `F_GLOBAL/F_ARRAY/F_PTR/F_FOR/F_BIT`）。
- **薄 ddmin**：`tools/minicc/diffsynth/ddmin.sh` 行级 delta debugging，宿主 acceptance 谓词（gcc 接受 & hostminicc 拒绝 ⇒ 误拒 bug）把失败样例缩到最小触发子集（自检：multi-level pointer 样例 12 行 → 3 行）。

**验收**：原则 6 名实相符（有单测，或文档如实描述现状与计划）。

## 任务 5（P2，规划项）：CompilerContext 收敛（F3，§10.1）

**目标**：兑现 §10.1「V2 起收敛 CompilerContext、不再新增全局可变状态」。当前仍是 V1 式全量全局（`tok/src/syms/patches/labs/code/...` 约 20+ 个）。

**为什么现在是候选窗口**：自举不动点已锁定，三重回归网（miccboot + 宿主 44 + guest 端到端）是做无行为变化重构的安全网。越晚做，新代码挂在全局上的面越大。

**需要你权衡的关键约束**（本任务最微妙处）：

- `minicc.c` 与 `minicc_self.c` 存在**行为严格一致纪律**；

- 若引入 `struct CompilerContext`：`minicc.c`（gcc 编译，全语法）没问题，但 `minicc_self.c` 必须落在 minicc 支持子集内——**minicc 不支持 struct**。对应路径有二：自举版用并行数组/指针模拟 context（保持子集纪律），或两版暂时不同构但语义严格一致；

- 纯重构 = 无行为变化：验收即全部既有测试零改动通过。

**验收**：P1==P2 仍逐字节一致；44+guest 全绿；全局可变状态数量有可核对的下降。

## 任务 6（P3，单独立项）：cc500 退役路线（F6）

**目标**：把「替代 GPL cc500」从能力达成推进到决策落地。minicc 已自举（能力条件具备），但 initramfs 仍嵌入 `cc500.c` blob（`tools/cc500/`、`test_cc500.sh`、shell 的 ccboot 链路都在）。

**这不是删文件**，先回答两个前置问题：

1. **许可核实**：cc500 实际许可证条款是什么？MIT 项目嵌入/分发 GPL 代码的兼容性如何处理（替代动机本就含许可，值得把结论写进 ADR）；
2. **依赖盘点**：哪些测试/命令/文档仍引用 ccboot/cc500（自举对照、教学对照）。

**参考路径**：(a) 分阶段退役——miccboot 升为默认自举路径，ccboot 降级可选对照，最终移除；(b) 保留为历史/教学对照但明确许可边界。建议产出一份 ADR（状态、决策、后果）再动仓库。

**时机约束**：排在 V4 特性对齐（任务 8）之后，避免在特性未补齐时过早断掉对照。

## V4 新增任务（本次讨论补充）

## 任务 7（P1）：minicc\_self 竞技场瘦身（616KB → 按真实峰值）

**目标**：`minicc_self.c` 预声明的大优化全局数组导致自举产物 686KB，其中约 616KB 是零填充数据段。

**思路（由 618 拆到低到贵）**：

1. **插桩测真实峰值**：自举编译时统计各池（节点/名字/解析栈/局部）实际使用上限，把 8192/4096 收到 peak+裕量，加边界守卫；
2. **字段瘦身**：小枚举字段（nkind/nty/nbty/nvkind…）由 `int`(4B) 改 `char`/`short`（子集已支持 char\[N]）；
3. **密集字节竞技场（中长期）**：稀疏平行数组合并为单一 `char arena[N]` + bump 指针，消除每池 slack；
4. **尺寸可配**：数组尺寸提成宏，同源码可编小/大镜像。

**收益**：`minicc_self_elf.o` 变小→嵌入 initramfs 后 3MB 磁盘预算减压；不破坏"免 malloc 自举"纪律。

**验收**：P1==P2 仍逐字节一致；产物体积有可量化下降；44+guest 全绿。

## 任务 8（P1，V4 最小切片）：`for` + 位运算

**目标**：补上文档 V4+ 里最小、风险最低的两个特性。

- **`for`**：语法糖，脱糖为 `while`+ 初值/自增，改动最小；

- **位运算** **`& | ^ << >>`**：x86 直发 `and/or/xor/shl/shr/sar`。**注意**：`&` 与现有"取地址"一元 `&` 重 token，需解析层区分（二元 & vs 一元 &）。位运算显著扩表达力（flags/掩码/hash），并顺带喂肥任务 7 的差分对拍（更多可生成表达式=更有效的随机源）。

**纪律**：per 文档「每增特性附一条测试」；宿主 t\_ 用例 + guest 端到端；`minicc_self.c` 若用到也必须落在子集内。

**验收**：`make test-minicc` 全绿（新增 for/位运算成功路径 + 拒绝路径断言）。

## 任务 9（P3，方向②自含体验）：in-guest 行编辑 / patch 原语

**目标**：持久化已具备（v0.16 ATA 写回 + `save`），补上"开机进系统不用宿主就能改码重编"的编辑体验。

**参考路径**：

- `patch <file> <line> <text>`：读整文件→按换行 splice→写回，\~200 行 C，低成本；

- ed 风格行编辑器：在之上叠显示/定位/替换命令层，\~300–500 行；

- 不推荐全屏编辑器（串口 128B 行缓冲、无终端控制）。

**验收**：guest 内能对已落盘源文件做逐行修改并 `micc` 重编，`save` 后重启改动仍在。

## 项目既有纪律提醒（跨任务适用）

1. **防假绿**：错误路径断言用症状对立（不得出现成功标志），成功路径断言运行语义而非编译产物存在；
2. **子集纪律**：`minicc_self.c` 任何改动不得超出 minicc 支持子集（违规即 bug）；
3. **双源一致**：`minicc.c` 行为变更需同步 `minicc_self.c`（反之亦然），P1==P2 是最终裁判；
4. **文档随码**：行为变更同步 `docs/design/minicc-design.md`（含 BUG 编号、roadmap 状态）；
5. **长任务后输出运维记录**，敏感操作前对齐。
