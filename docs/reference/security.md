# mini-os 安全威胁模型（显式化）

> 本文件把 mini-os 的**安全取舍与边界显式化**，作新品种录线与评审/红队的对账基准。
> 目的不是宣称"安全"，而是**把"为什么不安全是我们可以接受的"写成可 grep 的维护契约**——
> 新增子系统/驱动/字面量时，先对照本文件的"维护规则"自查。
>
> 生命周期：活文档。安全语义变更时更新；BUG/OBS 登记需在此给出"为何接受"摘要（见 `bugs.md`）。
> 对应本仓库 `docs/README.md` 清单，路径 `docs/reference/security.md`。

## 1. 信任边界模型

mini-os 是**单用户教学 OS**，其安全目标不是对抗恶意用户，而是：

1. **内核与用户（ring0/ring3）隔离不被破坏**——这是唯一硬性目标。
2. 故障**失败可观测**：要么杀进程、要么干净停机，不静默污染内核共享状态。

据此定下以下信任边界：

| 信任边界 | 说明 & 依据 |
|---|---|
| **单用户、无强互信隔离** | 同一用户加载的所有 guest 程序**相互不互信**的假设**不成立**——默认将 socket/IPC/共享内存视为共享资源（= OBS-003 有意设计，见 §3）。未来引入互不信任 agent 时须先补进程归属校验 |
| **磁盘/镜像可信假设** | 启动所用的 ramdisk / disk image 视为可信输入。曾因**恶意/损坏镜像中的块号**触发越界读写（红队 RD3，BUG-069/070）：块号取自镜像字段的路径必须做边界/归属校验（RD3 注记，块号校验规则见 §4） |
| **4KB 内核栈预算纪律（硬约束）** | 中断/系统调用均在每进程固定 4KB 内核栈上运行（L0 页底 canary + L1 多根链门禁，BUG-064 内核栈预算总账）。**任何新代码不得在中断上下文放大栈帧**；已由 `check_stack_budget.sh` 按调用链逐帧记账 |
| **中断门关 IF → 单链独占栈** | 中断门进入时内核自动关中断（IF=0），内核态处理期间**同一栈由单执行链独占**，不会被嵌套中断打断——这是 4KB 栈能成立的协同前提 |
| **异常隔离语义（SEC-01）** | 用户态异常 → **杀进程**（不污染内核）；内核态异常 → **停机**（panic + 寄存器/调用栈回溯，A-1 BUG-072）。二者泾渭分明，杜绝"用户态异常落入内核继续执行" |

## 2. 排序过的取舍与原因（为什么"不安全"被接受）

| 取舍 | 状态 | 原因（可接受的理由） |
|---|---|---|
| **无 NX / 无 ASLR / 无 PIE**（SEC-06，= OBS-011） | 有意不改 | 架构/教学优先：用户程序固定链接 `0x800A0000`，用户代码/栈/堆均 `0x7` P\|RW\|U 含可执行映射。**降级"代码注入+ROP"成本，但无提权路径**——页表 U/S 位隔离是根本防线（实测有效）。功能演示优先，对应 CWE-693 |
| **无多用户 ACL / 无文件系统用户权限位** | 有意不建 | 单用户模型，fs 权限按"块归属账本 + RO 标记"约束（RD5-V4，BUG-071）；引入多用户 ROL/ACL 超出当前目标 |
| **socket / IPC 全局共享**（= OBS-003） | 有意设计 | 将 UDP socket、消息队列、共享内存视为进程共享资源。网络侧仅 `netsock_close` 有归属校验（`netsock_close_if_owner`，F-0b），`send/recv` 不校验 pid（OBS-012）。**一旦出现互不信任的 guest 程序，必须为 send/recv 增加归属校验**（校验成本低，写法见 BUG-038） |
| **DHCP 应答源校验（A-2 ①）** | 已加固 | 超过"端口 68 + 可预测 xid"的原始分发：现要求 op==BOOTREPLY、UDP 源端口==67、已绑定则源 IP 匹配（RFC 2131 §4.1，红队 C2 enabler）。**源头校验收紧，不改状态机（RENEW→REBIND 回退另立项）** |
| **syscall 参数"符号/哨兵"语义（A-2 ②）** | 已统一口径 | 负 fd/负长/容量类参数的**处理原则**集中为一张语义表（见 `usermode.c` dispatch 头部注释；本文件不再复制）。重点：sem_create 负 init → 显式拒绝（SEM-1，审计误报根因）；剩余靠既有 `user_ptr_valid` / clamp 兜底并补注释 |

以下各项的完整记录见 `bugs.md`；这里只摘"为何接受/当前处置"一句话：

| 项 | 摘编 | 为何接受 / 处置 |
|---|---|---|
| OBS-003 | socket/IPC 全局共享无归属 | 单用户教学模型的有意设计，见 §2 |
| OBS-011（SEC-06） | 无 NX/ASLR，用户区可执行 | 架构/教学取舍，页表 U/S 隔离兜底，见 §2 |
| OBS-012（SEC-02） | UDP send/recv 不验 pid | = OBS-003 的有意设计；close 已有归属校验 |
| BUG-066+（红队 F1/F2） | 按名加载缓冲契约、ccrun 假成功 | 契约对齐 + 判败硬化（bug/修复记录） |
| BUG-069/070（RD3） | 镜像块号越界读写 | 已修：块号边界/归属校验；本文件 §4 块号校验规则 |
| BUG-071（RD5-V4） | 合法范围内重复块跨文件读写 / RO 绕过 | 已修：块归属账本 |
| BUG-072（A-1） | 内核 SSP + panic 回溯 + ring3 chaos 探针 | 已加固：栈损坏可观测、内核态异常干净停机 |

## 4. 维护规则：新增子系统/驱动必须自查的安全属性

新增任何子系统、驱动或用户可见接口时，对照下列自查（**门禁 checklist**，随 PR 补充说明每条命中的取舍）：

1. **栈预算**：是否在中断/系统调用热路径放大帧？新调用链帧内缓存是否触 4KB 预算（`check_stack_budget.sh` 逐链记账）？能否下沉到"非中断上下文"再做大缓冲？
2. **copyin 全链路**：任何从用户指针读/写的数据，是否经 `user_ptr_valid` 验**整区间** + `copyin/copyin_str` 拷入内核缓冲后再用？输出参数 `copyout` 前是否回验目标区？（v0.17 起基线，新增处不得旁路）
3. **只读（RO）属性**：写路径是否绕过文件的 RO 标记 / 块归属账本？新写的落盘字段是否允许越权改写他人文件（核对 BUG-071 的账本语义与 `sched_fd_revoke`）？
4. **块号校验**：从磁盘/镜像/载荷**读入的块号、偏移、长度**，在用于索引/拷贝前是否完成**上界与归属**双重校验（RD3 教训，BUG-069/070）？
5. **参数符号/容量**：新 syscall 入参是否按 `usermode.c` 头部"参数语义表"①~⑤ 对照——长度/容量是否 clamp、负值是否有无符号化语义、指针是否整区校验、id/槽位是否 `0||>=N` 双检？
6. **共享资源归属**：新 socket/IPC/共享页是否沿用"单用户共享"现设计？若将承载互不信任 payload，须提前加归属校验（见 §2 OBS-003 注记）。
