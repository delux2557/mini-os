## 1. 数据与规模

- 内核 `src/` ≈ 1.27 万行 C/asm（不含测试/tooling）；`.c`×56 / `.h`×36；子系统行数：kernel 2.6k / app 2.6k / drv 1.5k / net 1.1k / fs 0.8k / mm 0.6k / arch 0.2k。
- Git：73 次提交、5 分支；`docs/` 含 bugs.md / design.md / roadmap / changelog / external-reviews / 外部实测交接单。
- cc500 为**客机内自举编译器**（受限 C 子集，P1==P2 逐字节不动点校验）。

## 2. 分层架构（评估：优秀）

- 目录按 MINIX 风格分服（arch/kernel/mm/drv/fs/net/app），`VPATH + -I` 使子目录源可裸名引用，增删模块成本低。
- **netif ops 表抽象**（`netif.h`）：IP 数据报为单位，链路层成帧下放适配层（e1000↔COM2 SLIP）；`test-slip/test-tcp` 实证"换卡协议层零改动"。此为 HAL 正解。
- **纯逻辑抽取**（`guard.c`/`sched_policy.c`/fs/net）：判定函数无副作用 → 宿主 `run_host_tests` 秒级验证第一层，成本低收益高。

## 3. 数据模型与并发（评估：合理，有单核假设）

- PCB 以状态机枚举（`PROC_* × BLOCK_*`）编码资源账本，配 `sched_audit()`/`mem_audit()` 运行时可验证一致性。
- **并发 = 单核无锁假设**：就绪队列/信号量无锁。对 QEMU 单 vCPU 成立，但属**未显式文档化的架构约束**。
- 驱动层（e1000 中断 vs 主动收包、kb/COM1 IRQ 共享路径）靠"针对性修复"（如 K1 整行 IRQ 原子化）而非设计保证 → 需要固化不变量。

## 4. 地址空间与内存（评估：正确，刚度高）

- 用户地址空间由头文件宏**完全静态规划**（栈 32KB/槽、app 1MB、heap 320KB 固定虚拟地址）。
- 优点：map/guard/brk 可写成纯逻辑被单测覆盖；正确性由帧配平 + OOM 降级保护。
- 代价：无动态地址空间分配；"编译期未知进程数/布局"不可表达。

## 5. 验证体系（评估：最大亮点）

| 层 | 工具 | 作用 |
|---|---|---|
| L1 | `run_host_tests.sh` + `fuzz_parse.c`(ASan/UBSan) | 秒级纯逻辑 + 畸形输入免疫 |
| L2 | `qemu_regression`/`test-serial` | QEMU 键盘/串口关键字回归 |
| L3 | `test-net/slip/tcp/det` | 换卡、协议、确定性 |
| L4 | record/replay：`transcript.sh`+`tr2sqlite`+`replay.sh` | 现场固化→检索→复原闭环 |
| L5 | CI(regression multi-job) + `tests/arena` 独立评测 | 自动化 + 外部可复现评测 |

- 诚实对待 flake：`test-tr-stable` 连跑 3 次、"0 假红"显性化、如实记录"修复前 ~40-67% flake"。
- 可观测性收口：`selftest` 单行汇总 + harness 退出码 0/1/2 语义 + 失败现场转储。
- 缺陷可追溯：注释带 `v0.x`/`BUG-xxx` 版本戳（如 guard.c 记录 BUG-030 fork 槽位误判动机）。

## 6. 结构性风险与债务

1. **单核无锁假设未文档化为不变量**（P1）
2. **地址空间布局硬编码**（P1，演进性）——应至少在 design.md 固化"此为定格布局"决策
3. **PCB 近 40 字段过度膨胀**（P2）——建议抽 `resource_t` 记账结构
4. **演示应用体量失衡**（P2）——`src/app`≈2.6k/12.7k，绝大多数 app 固定地址 + ELF blob 内嵌
5. **QEMU 重负载集成套件是验证体系实时性短板**（P2，已被自知）——`make test` 12 个 QEMU 目标分钟级
6. **工具链豁免与版本敏感**（P2，已被文档化管理）——cc500 的 permerror 豁免依赖 GCC 版本
7. 小项：`qemu_regression.sh` monitor socket 固定 `/tmp/minios-mon.sock`（并发同跑会撞）；`_build_env.sh` 等新文件缺末尾换行（与既有风格一致）

## 8. 演进建议（按性价比）

1. 把"单核/关中断/原子段"固化为一节设计文档不变量（零代码成本）。
2. 抽 `resource_t` 记账结构收敛 PCB，统一"资源释放回调"。
3. `qemu_regression.sh` monitor socket 改 `$BUILD` 派生，兑现 BUG-053 全量隔离。
4. cc500 豁免项加 **CI 工具链版本矩阵检测**，把 GCC 13/14 差异自动化。
5. 长期：在 roadmap 明确"定格布局 vs 去固定地址"二选一，避免摇摆。
