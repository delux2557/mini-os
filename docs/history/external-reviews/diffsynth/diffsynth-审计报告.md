## 1. 审计对象：它到底是什么

diffsynth 是 minicc 的**随机差分对拍网**（mini-Csmith），由四个组件构成，实际形成三层能力：

| 组件 | 能力 | 每次覆盖量 |
|---|---|---|
| `gen.c` | 特性表驱动的 C 子集生成器（"mini-Csmith"）：20 个 F_* 特性位、能力集门控（minicc/cc500 两档）、无 UB 三纪律、自覆盖探针 | 每例 ≈30 行源码 |
| `run_diff.sh`（宿主层，MVP-A） | 哨兵（gcc 可编译）→ 确定性双跑 → **acceptance 差分**（gcc 收而 minicc 拒 = bug 候选）；崩溃/挂起分计；违例留档 `violations/` | count=10~20 |
| `gen_guest_elfs.sh` + `test_diffsynth_guest.sh`（guest 层，方案 B） | **运行语义差分**：12 个样本编成 ELF 嵌入 initramfs，guest `run dsXX` 退码 vs 宿主 gcc 参考退码 | **12 例**/CI |
| `ddmin.sh` | 行级 delta-debugging 最小化器（可插拔谓词 `DD_PROG`） | 按需 |

判定口径：程序 `return EXPR`，gcc 侧退码（qemu-i386 跑 `-m32` 参考程序）与 guest `run` 退码按 8 位比对。

## 2. 审计方法与本环境

1. **源码审计**：gen.c 全部 20 个特性位的 pick 逻辑、三纪律的落实点、run_diff/ddmin/guest 三处的判据与边界。
2. **生成器实测**：`gen_audit.sh`（随包交付）——把他们生成器的产出接进**运行语义差分环**：gcc（native）参考退码 vs minicc 产物（freestanding runner `runmin32`）真实执行退码，每例兼做确定性双跑与 UBSan（有符号溢出/移位）检查。这比他们宿主层（acceptance-only）更进一步——补上了他们文档标注"列为下一步"的宿主运行语义差分。
3. **形态覆盖审计**：以上轮 minicc 报告的 9 个缺陷触发形态为清单，逐一核对"生成器能否产出该形态"。
4. **环境说明**：本沙箱无 QEMU、无 32 位 libc——`run_diff.sh`/`ddmin.sh` 的 qemu-i386 硬依赖无法满足，故宿主运行差分由 `runmin32`（minicc 产物执行器）等价承载；runner 忠实度已由"旧谱系自举 P1==P2 在同一 runner 下成立"交叉验证（见 minicc/cc500 报告）。

## 3. 生成器实测数据（可靠性主证据）

4 组参数（多 seed、加压），每组 = 生成 → gcc 编译+两次运行（确定性）→ UBSan 运行 → minicc 编译 → 产物执行退码比对：

| 配置 | 例数 | gcc 拒编 | 确定性错 | UB 程序 | minicc 拒编 | 语义偏差 | 产物崩溃 |
|---|---|---|---|---|---|---|---|
| seed=100, vars=6, stmts=8 | 400 | 0 | 0 | 0 | 0 | 0 | 0 |
| seed=7, vars=8, stmts=30（加压） | 250 | 0 | 0 | 0 | 0 | 0 | 0 |
| seed=99, vars=8, stmts=30 | 250 | 0 | 0 | 0 | 0 | 0 | 0 |
| seed=2026, vars=8, stmts=30 | 250 | 0 | 0 | 0 | 0 | 0 | 0 |
| **合计** | **1,150** | **0** | **0** | **0** | **0** | **0** | **0** |

- 覆盖探针：4 组均**无告警**（声明的 20 个 F_* 全部实际产出）✓。
- 结论：**生成器在其形态空间内是确定、无 UB、高接受的**；minicc 对该形态空间的翻译与 gcc 完全一致。作为"回归网"它现在就是绿的、且可复现。

## 4. 架构与工程细节审计（值得肯定的部分）

1. **无 UB 三纪律大体落实**：声明即初始化（含数组全元素）、除/模分母恒为非零小常数、循环计数守卫（`_g<20`/`for 8 次`/`_d<20`）、递归模板参数 `&3`/`&7` 限幅、动态下标 `((v%5)+5)%5` 双向夹取（评审 P2 修复）。
2. **自覆盖探针**：声明了 F_* 却未被产出的能力会在 stderr 告警——"声明≠可达"的自我警惕在同类工具里罕见（实测 4 组无告警 ✓）。
3. **工程细节**：确定性双跑、timeout-124 与"程序自身返回 124"的区分（`--verbose` 标记法）、违例留档 `violations/`（修复了 #106 的"下批 rm 覆盖现场"缺陷）、hostminicc 缓存"源新于二进制则重建"（两处 P0 修复）、seed 轮换、崩溃/挂起/拒绝三分计。
4. **guest 层是真实的运行语义差分**：口径干净（退码 vs 退码、单一判据防假绿）、minicc 拒样本显式占位 + guest run 显式 FAIL。
5. **ddmin 设计合理**：经典 Zeller 粒度折半 + 可插拔谓词（`DD_PROG`）+ "gcc 拒=好"防把语法破坏误当触发。

## 5. 覆盖面审计：9 个 minicc 缺陷 0/9 可被生成

上轮 minicc 报告的 9 个缺陷（本轮已在新 main 复验：**6 已修 / 3 未修**），其触发形态与生成器能力的对照：

| 缺陷（状态@387ef62） | 触发形态 | 生成器为何产不出 |
|---|---|---|
| MC-01 空条件 `for` → ELF 头损坏（**已修**） | `for(;;)` / 空段组合 | for 模板恒为 `for(_i=0;_i<8;_i=_i+1)`（gen.c:197） |
| MC-02 标识符 >31 字符 → 编译器栈溢出（**已修**） | ≥32 字符标识符 | 标识符恒为 `v%d`/`G%d`/`a%d`（≤4 字符） |
| MC-03 数组字节数 int 溢出（**已修**） | `int a[600000000]` / `int g[2^30]` | 数组恒为 `int a%d[5]`（ASZ=5，gen.c:53） |
| MC-04 arity 错配（**已修**） | 实参数≠形参数 | 调用模板 `h%d(单个 masked 参数)`，恒 1 参 1 实 |
| MC-05 `a[0x10]` 十进制环 → 错尺寸（**未修 ✗**） | 十六进制数组维度 | 维度恒为十进制字面量 5；数字字面量恒为十进制（`rndi(1,100)`） |
| MC-06 源码 NUL 静默截断（**已修**） | 源码含 `\x00` | printf 文本路径无法产出 NUL |
| MC-07 八进制/空 `0x` 字面量（**已修**） | `010` / `0x` | 数字恒为十进制（同上） |
| MC-08 函数重定义静默接受（**未修 ✗**） | 同名函数定义两次 | 每个函数名只定义一次（h0/h1 固定模板） |
| MC-09 递归无深度守卫 × 28KB 栈（**未修 ✗**） | ≥45 层括号 / ≥1,000 项加法链 | 表达式 `MAXDEPTH=4`、语句模板扁平（循环体恒为单条赋值，无嵌套控制流） |

**结构性结论**：9 个缺陷分布在"词法边界、资源上限、声明形态、控制流形态"四个生成器刻意不去的象限。`gen.c` 的定位是"无 UB 安全子集的值语义回归"——它对**值语义**的回归很有效（本轮 1,150 例零偏差再次证明），对**结构/边界/资源**类缺陷系统性失明。此外语句模板恒为"单条赋值"或"单层模板"，**没有嵌套控制流**（循环套 if、if 套循环），标签/跳转类 codegen 交互（正是 MC-01 的病灶）在形态上不可达。

> 佐证：把 9 个触发形态做成"形态注入清单"后，仅空条件 `for` 一项，随机族中 81/81 含该形态的产物全部 ELF 头损坏（见 minicc 报告 §4 MC-01）——即"形态一旦可达，捕获率 100%"。缺的不是灵敏度，是形态。

## 6. CAPS_CC500 过期：cc500 新特性零覆盖

- `gen.c:36-38` 的 `CAPS_CC500` 注释："2026-09-05 实测校准：hostcc 探测 rc——global/array/ptr/for/~/^ 全部拒"，能力集 = `F_CONST|F_VAR|F_ARITH|F_CMP|F_LOGIC|F_IF|F_WHILE`。
- **实测复核（本次）**：`--target cc500` 产出的 3 个样本仅含 `while/if/算术/比较`，grep 证实 `for/do/~/^/%/+=` 零出现。
- 而 cc500 在 09-05 之后已合并 **M1**（for/do-while）、**M2**（一元 -/!/~、^）、**M3**（* / %）、**M4**（复合赋值）、**M5**（break/continue）、**M6**（短路 &&/||）——即差分网对 cc500 的**全部六个里程碑零覆盖**；连 `gen.c` 注释自认"cc500 支持 char"的 `F_CHAR` 也没进 `CAPS_CC500`。
- 影响：cc500 的增量（与 minicc MC 系列同类的高危区：循环回填、一元链、复合赋值 lvalue）完全游离在差分网外。cc500eval 包（另交付）已用独立差分网补测（44 定向 + 2,200 随机零偏差），但那是一次性评估，**不是常驻 CI 资产**。
- 建议：按 cc500 M1–M6 重新校准 `CAPS_CC500`（probe 法他们已有），并把 `--target cc500` 的生成也接入 guest 差分层。

## 7. UB 纪律的论证缺口（理论审计）

- 文档声称"变量/表达式维护保守区间并夹取到 ±2^28"。**实测代码**：`expr_gen` 的 `*lo/*hi` 只作用于**当前表达式**的返回区间；`E_VAR` 对变量**硬编码 `[0,100]`**（gen.c:113-114），与该变量实际被赋过的值（可被此前语句写成 ±2^28 量级）完全脱节——**区间记账是虚构的**。
- 实际防溢出的机制是隐式的：叶子 ∈ [1,100]、乘法右值恒为常数 [2,9]、表达式深度 ≤4 ⇒ 单表达式上限 ≈100×9⁴≈6.6M；跨语句链式放大（`v=(v*9)` 连写）理论上可在 ~10 条语句后触及 int 溢出，但需要同一变量被连续选中做乘法赋值（概率低）。
- **实证**：1,150 例（含 stmts=30 加压）UBSan 零触发。结论：**"目前安全"成立，"有论证"不成立**。建议二选一：(a) 变量值域真跟踪（记录每变量的实际 lo/hi）；(b) 语句级显式夹取（生成 `lv=(expr)%100000` 类模限幅），让无 UB 成为构造性保证而非概率保证。

## 8. ddmin.sh 审计

- 设计好：经典 Zeller 粒度折半；**可插拔谓词 `DD_PROG`**（本次审计即用它把谓词换成"运行语义差分/产物体检"）；"gcc 拒=好"防止把语法破坏误判为仍触发。
- 两个硬依赖挡路：`command -v qemu-i386` 与"hostminicc 必须能由 gcc -m32 构建"——**即使提供了 `DD_PROG` 也被无条件检查挡住**（本沙箱即被挡，需伪造 qemu + 预置 hostminicc 才绕过）。建议：`DD_PROG` 存在时跳过这两个依赖检查（语义上此时不需要 hostminicc 与 qemu）。
- 默认谓词只覆盖 acceptance 差分；运行语义差分的失败样本最小化需要自定义谓词——建议随包提供一个基于 guest 退码（或 runner）的现成谓词。

## 9. 建议清单（按性价比）

1. **形态清单化注入 gen.c**（最高性价比）：把 9 个缺陷的触发形态做成 gen 的"边界形态模板"（空条件 for、`a[0x10]`、长标识符、重定义、深嵌套、NUL 用环境注入），每个模板一条——按本次实测，"形态一旦可达，捕获率 100%"。
2. **刷新 CAPS_CC500** 到 M1–M6 + F_CHAR，并把 `--target cc500` 接入 guest 差分层（cc500 的六个里程碑现在完全游离在网外）。
3. **guest 差分样本量 12 → 50+**（QEMU 一次启动可批量跑，边际成本极低），并做 seed 轮换。
4. **宿主运行语义差分并入 run_diff.sh**：用 freestanding runner（本包 `gen_audit.sh` 模式）在无 QEMU 环境也能跑运行语义比对——他们文档里"列为下一步"的事项，本次已验证可行（1,150 例零误报）。
5. **UB 论证补齐**（§7 的 a/b 二选一）。
6. **ddmin 依赖放宽**：`DD_PROG` 存在时跳过 qemu/hostminicc 检查；随包提供"运行语义差分谓词"。
7. 把 `repro.sh`（9 缺陷复现）与 diffsynth 并列为互补资产：diffsynth 管"值语义回归"，repro 管"结构/边界回归"——两者判据正交，合起来才覆盖 minicc 报告的全部缺陷类别。
