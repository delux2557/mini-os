# MTU/大包失败路径规范（netif Step 4，第 3/3 份语义规定）

> 版本 v1.1（2026-09-01 收尾修正）。**动码前定稿。** 定义单包尺寸上限及超限时的失败路径选择。

## 1. 硬墙上限

| 传输层 | 单数据报/载荷上限（含 8B 会话协议头） | 分摊明细 |
|--------|------------------------------------------|----------|
| **薄包装有效上限** | **≤1400 字节** | 最终约束：netsock `sendto/recvfrom` 在系统调用层钳制 1400（见 usermode.c），一切收发数据报 ≤1400 |
| e1000（以太网）名义 | ≤1472 字节 | 以太网 MTU 1500 − IP 20 − UDP 8 = 1472（名目值，被 1400 钳制涵盖，仅理论上限） |
| COM2 串口（SLIP）名义 | ≤1600 字节 | 适配层缓冲 1600B（含 SLIP END；名目值，被 1400 涵盖） |

**结论**：薄包装**发送**上限取 1400（`tcp_send` 硬墙，超限本地早返 -1）；**转发器下行**按
≤1400 分块 (`TCP_MTU`/`CHUNK`)；接收侧由 `NET_RXMAX=2048` 分派 + 接收环 `TCP_RXB=4096`
重组，**一次 >1KB 响应完整不截断、尾字节完好**。这三处是同一份约束的收、发、转发三落点
（v1.1 收尾：Net_RXMAX 512→2048、环 1024→4096、转发器下行分块 1392——把此前">512 被静默
截断 / 环 1024 丢尾部"的容量缺陷一次性归并修复）。

超限报文**不被发送**，失败路径见 §2。

### 1.1 为什么是硬墙（而非动态协商）

- 两个上限均来自**编译期固定缓冲/硬件约束**，无运行时链路 MTU 发现机制。
- 硬墙避免了"分片-重组"的复杂度（分片与 TCP 语义冲突，厚包装也不引入分片）。
- 应用层协议（HTTP/1.x 短连接）天然适配单包上限；厚包装后续可缓存分段，但薄包装维持"一次 send 发一条报文"。

## 2. 超限失败路径：**guest 报错误码**（写死）

单包载荷超出 §1 上限时，**不产生任何报文**（不发给转发器），失败完全由 guest 侧薄包装本地判定：

```
tcp_send(fd, data, n) → 若 n > 单包上限 → 立即返回 -1（本地失败）
```

- 不依赖转发器回事件，不占网络带宽，不产生孤儿会话状态。
- 转发器侧**不会收到**任何超限报文，因此转发器没有"超限检查"义务。
- 错误码 `-1` 的精确语义见 `tcp-thin-api.md` §1：`-1` = 本地失败（含超单包上限）。

### 2.1 实现位置

检查在 `tcp_send()` 入口执行，在 `netif_tx()` 调用之前：

```c
int tcp_send(int fd, const uint8_t *d, uint32_t n) {
    // ... 校验 fd ...
    if (n > SESSION_MTU_MAX) return -1;     /* 硬墙早返 */
    // ... 构建会话头 + 载荷，调 netif_tx ...
}
```

`SESSION_MTU_MAX` 按当前活动的网卡后端取 `netif_info()->mtu`（或编译期取二者较小值——实现时定）。

### 2.2 为什么不选"转发器回事件"

- 超限完全是 guest 侧可控错误（发送方知道自己的上限），不需要转发器介入。
- 转发器回事件引入**额外延迟**（UDP 来回），且转发器需添加"UDP 载荷 > 上限则丢弃并回事件"的检查逻辑，增加转发器复杂度。
- 设计原则：**本地可判的错误，本地早返**，不依赖网络往返。

## 3. 实现期约束（写进 PR 描述）

### 3.1 栈预算：每层 ≤1 缓冲（ISR/系统调用链）

`netsock_drain` 的 `f[1600]` 与适配层缓冲合并传递，**ISR 到系统调用链上每层最多一个缓冲**：

```
netsock_drain（f[1600] 栈缓冲）→ 构建会话协议头原地填入 f 前 8 字节 →
  netif_tx（f 指针 + 总长直传）→ 网卡适配层（e1000 追加以太网头 / SLIP 编码，
  适配层有自己的发送缓冲，但 f 在此层释放，不跨层拷贝）
```

- 禁止在 `netsock_drain` 之外再分配一个"合并缓冲"。
- 接收路径同理：`netif_rx` → `tcp_dispatch` 解析会话头并原地提取载荷，不额外拷贝。
- 这样做的好处：内存开销可预测、无动态分配、适合 ISR 上下文。

### 3.2 串口模式 IP 是名义地址

SLIP 通路上实际依赖的 IP 是 DHCP 回落静态 10.0.2.15（guest）、宿主对端可冒充 10.0.2.2（SLIRP 兼容）。会话协议对地址无假设（已在 `tcp-session-proto.md` §4 文档化）。调试串口 demo 时勿被名义 IP 绕路。

### 3.3 测试计划

| 编号 | 测试项 | 方法 | 断言 |
|------|--------|------|------|
| 1 | 会话头解析 fuzz | 复制 PR13 模式进 `fuzz_parse.c`（case 7）：随机 0-64 字节输入 + 随机偏移切割 | 不崩溃、不越界读 |
